# [title tbd — options: "help me learn, be slow" / "the .md file" / "i stopped for a few days" / "more consistent, more mine"]

a few months back i was constantly fighting with figma make. i had my design system ready but the tool only let me share up to frames. i couldn't get the whole thing across, so i kept splitting it, losing context, starting over.

that was my setup for a while: lovable for quick prototypes, ai studio for ideas, figma make for getting something in front of the team fast.

then the conference swags started showing up everywhere. people posting bags and stickers from events i wasn't at, and something in the back of my head went: am i missing something? do i know less than i think? i don't think so. but it got to me.

so i tried claude. for about a month i couldn't figure out why people were so excited. the outputs weren't good even when i was genuinely trying. [this meme](add link) made me feel seen. [this tweet](add link) was funnier because it was exactly what i was feeling.

then i stopped. for a few days i didn't touch any of it. the internet was starting to feel like a place where everyone was generating something in ten minutes while i was spending hours getting something mediocre.

when i came back i changed one thing. i gave claude my figma file and a PRD instead of asking it to generate. ux fine, placement fine, but it still generated its own visual choices even though i'd given it my design. not quite right.

what helped was a half and half window: claude on one side, claude code on the other. i told claude i was overwhelmed and asked it to slow down: help me learn, be slow, divide everything into steps. whenever i got stuck i took a screenshot and asked. it would explain, i'd try again, it would point me back.

at some point claude mentioned .md files. i'd been seeing that term everywhere, first on google stitch, then constantly after. this time i actually sat with it. two to three hours to build one for my design system. when it was done it felt genuinely cool.

after that the outputs got more consistent, and more mine. that's when the analogy clicked: what svg is to icons is what a .md file is to design systems. svg stores a visual asset in portable, machine-readable, human-readable form. pass it anywhere and it renders. a .md file does the same. pass it to claude code, to figma, to antigravity, and each one reads from the same source. it doesn't document the system. it carries it.

building the file, i started thinking in three layers. layer 1 is tokens: colors, typography, spacing, shadows. layer 2 is components: how those tokens combine into ui pieces. layer 3 is patterns: how they behave in context. that maps directly onto brad frost's atomic design, which i kept coming back to the whole time.

once those layers are in place, what's left is thinking. a PRD and a .md file should be enough. i see myself using figma less and paper wireframes more. the time that used to go into perfecting pixels can go into thinking and validating instead. that part is more interesting to me anyway.
